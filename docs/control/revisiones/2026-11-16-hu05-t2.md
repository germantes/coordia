# Decisión de producto · HU-05 · T2 (16/11/2026)

Tarea [869fc6zwa](https://app.clickup.com/t/869fc6zwa). PO: Alejandro Cerezo Contreras. Revisor de T2: Fernando Bravo Torres. Responsable: Damián Verde.

El prototipo de T1 (`docs/test_edge_cases.py`) resta 0,30 cuando varias cuentas confirman el mismo reporte compartiendo IP, subred o dispositivo, y 0,40 cuando hay tres o más confirmaciones distintas en menos de 30 s.

T2 **no aplica el −0,30 por coincidencia de origen**. HU-04 pide confirmaciones de personas cercanas; en el campus, el barrio o el mismo operador esas cuentas comparten IP, y el recorte marcaría el caso honesto. La subred es peor. Un identificador de dispositivo sí separaría “un móvil, muchas cuentas” de dos personas en el mismo Wi‑Fi, pero el cliente no lo envía.

T2 **sí aplica** el umbral de verificación, el historial de transiciones y el **−0,40** por tres o más confirmaciones de personas distintas en una ventana de menos de 30 s.

El −0,30 de origen compartido queda **fuera de este sprint**. Vuelve cuando exista un `device_id` de cliente o se rediseñe con un umbral alto (tres o más cuentas, no dos). Es un recorte de esa regla de T1, no un aplazamiento porque la API no pueda guardar la IP.

No se cambia la línea base `LB-S2-v1`. No se retiran HU-05 ni T2.
